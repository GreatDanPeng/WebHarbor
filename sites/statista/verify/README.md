# Statista deterministic grading (review track)

All 23 tasks in `../tasks.jsonl` have a rubric and a deterministic verifier.
Ground truth lives only in the verifiers (hardcoded from the frozen seed);
answers never appear in the agent-facing task file, and `tasks.jsonl` keeps
its original 5 keys as a byte-identical prefix with `verifier_path` +
`judge_rubric` appended (`append_rubrics.py`, idempotent).

- `verify_lib.py` validates the task wording and ID, completion, loopback
  origin/port, decodable screenshots, and the SQLite seed contract (frozen
  schema/row digests for the deterministic build, md5 d6302969…), and exposes
  the stateful-delta helpers (registered user with bcrypt-format hash,
  favorites add/remove, download events).
- `verify_0.py` … `verify_22.py` are the per-task entrypoints (generated by
  `make_verifiers.py` from the centralized ground-truth table). Each gates the
  on-site navigation the task names (anti knowledge-shortcut), checks the
  answer deterministically, and pins the exact allowed database delta —
  read-only tasks require row-identical snapshots, stateful tasks the precise
  row additions/removals and nothing else.
- `tests/` contains the frozen honest fixtures (from the reviewer's live
  walks on the review container) plus adversarial controls: no-op runs,
  wrong answers, homepage-only shortcuts, state mismatches, wrong deltas,
  read-only database tampering and package tampering (task_id mismatch,
  off-site URLs, missing/undecodable screenshots, non-done trajectories).
  These fixtures are grading tests, not browser completion evidence; the live
  honest walkthroughs live in the review evidence directory.
- The seed DB resolves from the review container (`wh-statista-review`);
  `STATISTA_TEST_SEED_DB` / `WH_CONTAINER` override it.

Run from the repository root with pytest:

```bash
python3 -m pytest sites/statista/tests sites/statista/verify/tests -q
```

The official deterministic grader is primary. The optional LLM judge is
secondary; it was not run for this scripted browser review.

Task notes (fixture caveats found by the review, see the review report):
- Task 13's "first chapter in its table of contents" resolves to the
  'Description' heading — the visible report TOC for in-depth market
  analyses reproduces the upstream anonymous view (Description / Content /
  Tables + description text) and contains no real chapters.
- Task 4's "which plans can download reports" is answered from the pricing
  page (Personal and Professional list "Reports"); the application gates
  report downloads to the Professional Account only.
